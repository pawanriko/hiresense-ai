# 01 · Product Overview — HireSense AI (Candidate Edition)

## Vision
Candidates apply blind. They don't know why their resume gets rejected, which skills a job description actually demands, or what they'll be asked in the interview. HireSense AI closes that loop for the **candidate**: score the resume against the exact job, prove every score with evidence from the resume itself, turn gaps into a prep plan, and rehearse the interview — before applying.

**One-liner:** *Paste a job description, get your resume scored criterion-by-criterion with evidence from your own resume, see exactly what's missing, fix it with AI help, then practise the interview.*

## Core philosophy
- **Candidate-in-the-loop, always.** AI suggests; the candidate decides. Criteria and weights extracted from a JD are shown and editable before scoring.
- **Explainable over magical.** Every score is backed by a verbatim quote from the candidate's resume, or an honest "No evidence found". The composite score is computed by a deterministic formula — never generated by an LLM.
- **AI where it helps, rules where it counts.** LLMs do language work (criteria extraction, bullet rewrites, interview questions, feedback). Rules do measurement (evidence search, scoring rubric, ATS checks).

## The problem (candidate's side)
| Pain | How it shows up |
|---|---|
| Opaque rejections | "Fit" is a black box; candidates get no signal about what failed |
| Generic resume advice | Tips aren't tied to the specific JD being applied to |
| Unknown gaps | A missing required skill is invisible until the rejection email |
| Unprepared interviews | Questions are predictable from the resume + JD, but candidates practise blind |

## Target users
- **Primary:** students and early-career candidates applying for internships and entry-level tech roles (the builder is the first user).
- **Secondary:** any job-seeker who wants JD-specific, evidence-based resume feedback.

Explicitly **not** a user: recruiters/employers. There is no recruiter side in this product. (An earlier recruiter-side deck was reviewed and superseded on 23 Oct 2026 — see `08-decisions.md`.)

## Product modules (MVP)
1. **Resume Lab** — upload a resume (PDF/DOCX), parse it, and get an ATS health score with a category breakdown and concrete fixes.
2. **JD Match** — paste a job description; get a weighted match score with per-criterion evidence quotes, a gap list, AI bullet rewrites, a tailored resume version, and a cover letter.
3. **AI Mock Interview** — interview practice grounded in the candidate's resume + the target JD, with per-answer rubric feedback and a final report.
4. **Prep Dashboard** — an auto-generated prep checklist from the gap list, mock-interview scores over time, resume versions, and an application tracker (Applied → Interview → Offer).

## Scope boundaries
| Area | In MVP | Deferred (post-MVP) |
|---|---|---|
| Users | Candidates only, single-user accounts | Recruiter side, teams, sharing |
| Documents | PDF + DOCX parsing | OCR, image resumes, LinkedIn import |
| Scoring | Deterministic rubric + evidence search | Semantic/embedding-based matching |
| Interview | Text-based Q&A with rubric feedback | Voice answers (Whisper), live video |
| Delivery | Web app only | Mobile apps |

## Success criteria (portfolio-grade, "Top 5 project")
- Live deployed URL with a demo login.
- A visitor can run the full loop in under 3 minutes: upload sample resume → paste JD → see score + evidence + gaps → start a mock interview.
- Scoring is reproducible: same resume + same JD always produces the same score.
- README and docs (this set) let an interviewer understand the architecture without reading code.
